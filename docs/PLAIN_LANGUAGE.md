# HEBRA — Regla permanente de explicación sencilla

## Cómo debo explicarte cada movimiento

### Antes
**Qué voy a hacer**
Una frase.

**Por qué**
Una frase.

**Qué podría salir mal**
Una frase.

### Después
**Qué hice**
Una frase.

**Qué pasó**
Una frase.

**Qué cambió**
Una frase.

**Qué sigue**
Una frase.

## Ejemplo
“Voy a crear una segunda cerradura para que una sola llave robada no pueda abrir HEBRA.
Sirve para que un atacante necesite controlar varias partes independientes.
El riesgo es hacer el sistema demasiado complicado.

He probado una regla de 3 llaves de 5.
El sistema siguió seguro cuando robé 1 o 2 llaves en la simulación.
Ahora esa regla queda registrada como candidata, no como verdad final.
Lo siguiente es probar qué ocurre si además cae el servidor.”

## Palabras técnicas
Si una palabra técnica es necesaria:
1. primero explicarla en palabras normales;
2. después poner el nombre técnico entre paréntesis.

Ejemplo:
“una huella digital del archivo (hash)”.

## Regla
Nunca usar complejidad para impresionar.
La explicación correcta es la que permite al usuario entender:
- qué estamos haciendo;
- por qué;
- qué riesgo existe;
- cómo sabemos si funcionó.
