# HEBRA — Roadmap de Coste Cero v0.3

## Restricción
Gasto nuevo acumulado permitido antes de ingresos propios: **0**.

## Fase Z0 — Especificación y ruptura
Coste: 0
- Markdown/JSON/Python local.
- ICC-0 y modelo de amenazas.
- Especificación formal TLA+.
- Tests adversariales reproducibles.
- Datos exclusivamente sintéticos.
Salida: núcleo conceptual verificable.

## Fase Z1 — Repositorio público
Coste: 0
- Git.
- Repositorio público.
- Issues, discusiones, documentación.
- CI sólo en runners estándar gratuitos del repositorio público o ejecución local.
Salida: historial auditable y contribuciones.

## Fase Z2 — Sitio informativo estático
Coste: 0
- HTML/CSS/JS estático.
- Sin cuentas, pagos ni datos sensibles.
- Publicación mediante hosting estático gratuito apto para documentación/proyecto.
Salida: explicar HEBRA, especificación y cómo reproducir pruebas.

## Fase Z3 — Cliente local
Coste: 0
- Aplicación local-first.
- Crear Contratos de Resolución.
- Firmar/hashear localmente.
- Exportar CEI como archivos.
- Sin backend obligatorio.
Salida: primera utilidad real para personas sin coste de servidor.

## Fase Z4 — Piloto humano de bajo riesgo
Coste: 0
Dominios:
- aprendizaje;
- organización;
- hábitos cotidianos no clínicos.
Reglas:
- consentimiento;
- no datos sensibles innecesarios;
- no medicina, finanzas, derecho ni emergencias;
- preregistro;
- resultados positivos y negativos.
Salida: comprobar si una persona B mejora gracias a evidencia de A.

## Fase Z5 — Primer ingreso
Sólo después de alcanzar criterios mínimos de utilidad y seguridad.
Opciones:
- instalación privada;
- soporte/integración;
- auditoría del protocolo;
- cómputo gestionado;
- herramientas empresariales.
No:
- venta de datos;
- anuncios sensibles;
- pay-to-rank;
- cobro por alterar evidencia.

## Trigger de inversión
No se contrata infraestructura de pago hasta que:
1. exista ingreso real cobrado;
2. el gasto tenga retorno o necesidad de seguridad justificable;
3. exista alternativa de salida para evitar lock-in;
4. el coste máximo mensual esté presupuestado;
5. el gasto no sea necesario para verificar el núcleo abierto.

## Primera distribución del capital retenido
Durante bootstrap:
- prioridad absoluta: seguridad / auditoría / privacidad;
- después: infraestructura;
- después: accesibilidad / idiomas;
- después: adquisición de usuarios responsable.

La política económica debe revisarse con datos reales antes de fijar porcentajes permanentes.
